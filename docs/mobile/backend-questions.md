# 앱(React Native) 전환 - 백엔드 협의 항목

> 모노레포 전환(GLB-105) 과정에서 정리한 백엔드 확인 요청 사항입니다.
> 웹에서는 문제없지만 앱에서는 그대로 동작하지 않는 부분들입니다.
> 상태: 미확인 (확인 후 각 항목에 결과를 기록해 주세요)

## 1. 앱 로그인 (카카오 OAuth + 딥링크)

### 현재 웹 흐름

```
웹 → 백엔드 /oauth2/authorization/kakao?redirect_uri=https://globber.world/login/oauth/success
   → 카카오 로그인
   → 백엔드가 redirect_uri?accessToken=...&firstLogin=...&uuid=... 로 리다이렉트
   → 웹(Next route)이 토큰을 쿠키(kakao_access_token)에 저장
   → 이후 API 호출은 Authorization: Bearer <accessToken> 헤더 사용
```

### 앱에서 필요한 흐름

```
앱 → 백엔드 /oauth2/authorization/kakao?redirect_uri=globber://oauth/success
   → 카카오 로그인 (시스템 인앱 브라우저)
   → 백엔드가 globber://oauth/success?accessToken=...&firstLogin=...&uuid=... 로 리다이렉트
   → 앱이 토큰을 SecureStore에 저장
```

### 확인 요청

| #    | 질문                                                                                                                                                                                                    | 이유                                                                                 | 결과 |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ---- |
| 1-1  | `redirect_uri` 허용 목록(allow-list)이 있나요? 앱 커스텀 스킴(`globber://oauth/success`)이나 Universal Link/App Link를 허용할 수 있나요?                                                                | 허용되지 않으면 로그인 후 앱으로 돌아올 수 없음 (가장 먼저 확인 필요)                |      |

## 2. 장소/지오코딩 API (`/api/places`, `/api/geocode`)

### 현재 상태

- 두 API는 백엔드가 아니라 **웹(Next.js) 서버의 API Route**입니다 (`apps/web/src/app/api/`).
- 사진 GPS 좌표 → 장소명 변환(역지오코딩)에 쓰이며, 서버에서 Google Maps API 키를 숨겨 쓰는 프록시 역할입니다.
- 앱에는 Next 서버가 없으므로 같은 방식으로 호출할 수 없습니다.

### 선택지

| 방법                            | 설명                                  | 장단점                                                                              |
| ------------------------------- | ------------------------------------- | ----------------------------------------------------------------------------------- |
| A. 앱이 웹 서버 API를 직접 호출 | `https://globber.world/api/places` 등 | 가장 빠름. 웹 서버가 이 API를 계속 제공해야 하고, 인증/호출 제한이 없으면 남용 위험 |
| B. 백엔드로 이전                | 백엔드가 동일 기능을 API로 제공       | 가장 깔끔. 백엔드 작업 필요                                                         |
| C. 앱에서 Google API 직접 호출  | 앱에 키 포함                          | 키 노출 위험으로 비추천                                                             |

### 확인 요청

| #   | 질문                                                                                                 | 결과 |
| --- | ---------------------------------------------------------------------------------------------------- | ---- |
| 2-1 | 장소/역지오코딩 기능을 백엔드 API로 제공할 계획/여력이 있나요? (선택지 B)                            |      |
| 2-2 | 당분간 A로 간다면, 웹 서버 API에 인증(Bearer 검증)이나 호출 제한(rate limit)을 두는 것에 동의하나요? |      |
| 2-3 | 앱에서 사진 EXIF GPS 추출 후 장소명을 가져오는 흐름을 백엔드가 알아야 할 제약(쿼터, 비용)이 있나요?  |      |

## 3. 기타 확인 사항 (앱 출시 전)

| #   | 질문                                                                                                                                                                | 결과 |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| 3-1 | 이미지 업로드(S3 presigned URL)는 모바일(파일 URI 기반)에서도 동일하게 사용 가능한가요? (현재 `fileName`, `contentType` 전달)                                       |      |
| 3-2 | 회원 탈퇴 API(`/withdraw`)와 계정 삭제 기능은 스토어 심사 요건을 충족하나요?                                                                                        |      |
| 3-3 | 푸시 알림 도입 시 디바이스 토큰 등록 API가 필요합니다. 계획이 있나요?                                                                                               |      |
| 3-4 | 공유 링크(`/globe/{uuid}`)를 앱 딥링크(Universal Link/App Link)로 열기 위해 도메인에 `apple-app-site-association`, `assetlinks.json` 배포가 필요합니다. 가능한가요? |      |

## 진행에 미치는 영향

- Expo 앱 스캐폴딩, 화면 뼈대, 공용 패키지 연동은 **이 협의 없이도 진행 가능**합니다.
- **1번(로그인)** 은 앱 로그인 구현 전에, **2번(장소 API)** 은 사진 업로드/기록 작성 화면 구현 전에 결정되어야 합니다.
